# Bin API 与 AIHub 用户侧能力对比

对比日期：2026-08-03

## 结论

Bin API 已具备 API 密钥、精细用量、订阅支付、兑换码、渠道监控、公告、账号资料和多语言等核心能力。当前最大问题不是网关能力，而是新用户缺少一条清晰、可验证的上手路径。

优先级最高的工作是：上线站内教程、开放可用渠道页、补齐账号找回与邮箱验证、建立可访问的服务条款。供应商大厅的性能对比、邀请返利、模型广场等能力在代码中已经存在，但线上开关关闭，应先判断运营准备是否完成，再决定是否开放。

## 证据与范围

- AIHub 教程入口：`https://aihub.top/tutorial`。2026-08-03 自动化访问返回 Cloudflare 403，因此没有把无法读取的教程正文当作事实。
- AIHub 功能证据：工作区中 2026-07-29 保存的 API 密钥、供应商大厅、使用记录、个人设置等页面截图。
- Bin API 代码证据：`frontend/src/router/index.ts`、用户视图、API 密钥“使用密钥”配置生成器及相关后台实现。
- Bin API 线上配置：2026-08-03 请求 `https://api.binzzz.xyz/api/v1/settings/public` 返回的公开设置。
- 仅比较用户侧产品体验；上游账号池、调度、运维、风控等管理员能力不纳入横向评分。

## 优先级建议

### P0：直接影响转化与信任

1. **发布并持续维护站内教程**
   - 本次已新增 `/tutorial`，并在 `doc_url` 为空时让顶部和首页“文档”指向站内教程。
   - 上线后用一个全新账户完整走一遍：注册 → 支付/兑换 → 创建 Key → Codex/Claude Code 调用 → 查看账单。
   - 每次修改客户端配置生成器时，同步检查教程示例。

2. **启用密码找回和邮箱验证**
   - 当前公开配置同时关闭了邮箱验证和密码重置。
   - 配置 SMTP，验证注册邮件、重置链接有效期、重复请求限流及垃圾邮件投递。

3. **补齐并启用服务条款**
   - 当前协议结构存在，但内容为空且登录确认关闭。
   - 至少补齐服务条款、隐私政策、退款/订阅规则、支持地区和可接受使用政策。

### P1：降低首次选择成本

4. **开放“可用渠道”，升级为供应商大厅**
   - 代码已有 `/available-channels`，线上 `available_channels_enabled=false`。
   - 开放前确认每个渠道已配置说明、支持模型、分组倍率和用户可见范围。
   - 建议在现有表格补充首 Token、TPS、缓存命中、短期可用率和一键“使用此分组”。这些是 AIHub 供应商大厅最有价值的决策信息。

5. **开放用户可见的失败请求**
   - 当前 `allow_user_view_error_requests=false`。
   - 先确认错误信息已脱敏，再允许用户按状态码、模型、Key 查询失败记录，减少客服排障成本。

6. **完善首页与购买入口**
   - 当前 `home_content` 为空，`purchase_subscription_enabled=false`，但内置支付已开启。
   - 首页应直接呈现可用模型、倍率/套餐、状态页、教程和客服；购买路径应保持一个主入口，避免“支付开启但订阅入口关闭”的配置歧义。

### P2：增长与商业能力

7. **评估开放模型广场与邀请返利**
   - 两项功能均已有代码，线上开关关闭。
   - 开放邀请返利前先确认防刷、返利结算、退款回滚和财务对账。
   - 开放模型广场前确认模型名称、倍率、上下文、端点和可用性数据的更新责任。

8. **新增自助发票**
   - 这是对比中确认的真正功能缺口。
   - 最小版本包括：可开票订单、发票抬头、税号、邮箱、申请状态、驳回原因和文件下载。

9. **扩展登录方式与安全能力**
   - GitHub、Google、LinuxDo、微信、OIDC、Passkey 的代码或配置位已存在，但线上全部关闭。
   - 优先开放与目标用户最匹配的一种 OAuth，并保留邮箱登录作为恢复通道。

## Bin API 已有但需要更好呈现的优势

- API Key 支持总额度、5 小时/1 天/7 天窗口限制及 IP 黑白名单。
- “使用密钥”弹窗可生成多平台、多操作系统配置，不只是展示 Base URL。
- 使用记录筛选维度更细，并支持 CSV 导出。
- 管理侧已有更丰富的调度、监控、计费和账号池能力。
- 渠道状态具备自动刷新、多个时间窗口和详情视图。

这些能力应在教程和首页中以任务结果呈现，例如“限制单个生产 Key 的周预算”和“2 分钟完成 Codex 接入”，而不是仅作为后台表单字段存在。

## 验收清单

- 未登录访问 `/tutorial` 正常，移动端没有横向溢出。
- 登录后顶部“文档”在未配置 `doc_url` 时打开 `/tutorial`。
- 配置外部 `doc_url` 后仍优先打开外部文档，不破坏原有行为。
- 教程显示的 API Base URL 来自公开设置，不写死域名。
- 教程示例不包含真实 API Key、用户邮箱或模型凭证。
- 新用户可以仅依靠教程完成一次成功调用，并在使用记录中找到该请求。
- 401、403、429、404、5xx 的排障说明与网关实际响应一致。
